# 附录 A｜常用技术词汇与概念关系速查

本表用于项目评审时定位概念，不能仅凭记住缩写推断系统合格。例子均为模拟。

| 名称 | 在系统中的意义 | 容易混淆的边界 |
|---|---|---|
| 客户端 / Client | 发起请求的软件，如员工浏览器 | 用户可以修改请求，不能作为唯一可信校验方 |
| 服务端 / Server | 提供接口、执行业务规则的进程 | 不一定是独立物理机；一台机器可有多个进程 |
| API / 应用编程接口 | 调用者与提供者约定的交互边界 | 能调用不代表契约稳定、授权完整或可安全重试 |
| HTTP | 请求、响应和消息语义 | 状态码成功不代表业务数据正确或授权正确 |
| TLS / HTTPS | 对连接提供传输保护，HTTPS 使用 TLS | 不替代端点、日志、数据库或授权保护 |
| DNS / 域名解析 | 将名称解析到访问目标相关地址 | 解析成功不证明端口可达、证书正确或应用正常 |
| 端口 / Port | 设备上用于区分网络通信入口的编号 | 源代码存在不代表进程在该端口监听 |
| 认证 / Authentication | 确认调用者身份 | 登录成功不证明能查看所有数据 |
| 授权 / Authorization | 决定身份可以执行的动作与数据范围 | 隐藏按钮不是服务端授权 |
| Session / 会话 | 在多次交互间维持登录等状态的机制 | 状态存在哪里、如何失效需要具体设计 |
| Token / 令牌 | 调用时携带的某类凭据或状态表示 | 持有令牌可能意味着能操作，不能随意写日志 |
| 事务 / Transaction | 将一组数据库操作作为受控提交单元 | 数据库事务不自动覆盖外部 ERP 调用 |
| 幂等 / Idempotency | 重复同一业务请求不会重复产生预期副作用 | 不是每次返回完全相同的 HTTP 消息，也不等于“只执行一次” |
| 重试 / Retry | 失败或结果未知后再次尝试 | 超时不代表对方没执行，写入重试需要防重设计 |
| 对账 / Reconciliation | 按业务口径比较实际结果并找差异 | HTTP 请求数相同不代表订单或物料数据一致 |
| 缓存 / Cache | 保存可重新取得的数据以降低访问成本 | 缓存可能过期，不能未经设计当唯一权威来源 |
| 队列 / Queue | 将工作或事件与处理者解耦 | 消息仍可能重复、失败、积压，需确认和监控 |
| 镜像 / Image | 容器运行所需程序及文件的可分发模板 | 镜像不是运行中的容器，也不自动备份持久数据 |
| CI / 持续集成 | 自动执行检查、测试与构建 | 绿色结果仅代表配置的检查通过 |
| 回滚 / Rollback | 恢复到可用旧状态的受控过程 | 代码回旧版不保证数据库与外部写入也回旧状态 |
| RPO / 恢复点目标 | 允许丢失多长时间范围的数据 | 目标不是已经达成的恢复证据 |
| RTO / 恢复时间目标 | 期望多久恢复服务 | 需要演练验证，不只是写“立即恢复” |

## 看关系再看名词

员工查询链路通常是：浏览器发 HTTP 请求，经 HTTPS 入口到应用，应用认证并授权，再访问数据库。任何一个环节成功，都不能代替其他环节的验证。遇到故障时标明是地址、连接、身份、业务还是数据问题，再向 AI 提问。
