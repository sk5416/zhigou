# 读懂变量、条件、循环、函数和数据结构

## 结论先行

1. 读业务代码先找输入、判断、状态变化和输出，不必先记住全部语法。
2. 缺失、空值、零、负数与空字符串可能代表不同业务状态，不能随意互换。
3. 循环应能说明每条记录去了哪里，函数应说明参数前提及返回含义。
4. 数据量变大可能放大低效操作，但优化应基于规模与测量，不靠看到循环就否定方案。

## 业务场景：一百行物料只导入了九十行

模拟青禾制造有一批物料数量输入，AI 写出的程序跳过不符合条件的行，只返回成功列表。页面没报错，但你无法知道少的十行是重复、空值还是程序遗漏。读代码时应追问每行的去向和解释，而不是只检查最终数量看起来合理。

## 核心概念与系统位置

变量为值提供名称；类型约束值可参与哪些操作。数值 `5` 与文本 `"5"` 看起来相似，直接比较或计算未必具有同样含义。空值在 Python 中常写作 `None`，不应不加判断地当零处理。

列表保存一组记录，字典按键关联字段；函数将输入转换为输出，可能还产生写库、发消息等副作用。代码里的函数名不证明它实际只读或没有副作用，仍需检查其调用。

## 工作原理：沿一条记录走一遍

下面是纯内存模拟，数量的输入前提为数值或 `None`，业务规则仅为本例“创建正数量记录”。它不是完整导入实现。

```python
# 保留每行去向，不把错误记录悄悄丢掉
def valid_rows(rows):
    accepted, rejected = [], []
    for row in rows:
        code = row.get("code")
        quantity = row.get("quantity")
        if not code or quantity is None:
            rejected.append(row)
        elif quantity <= 0:
            rejected.append(row)
        else:
            accepted.append(row)
    return accepted, rejected
```

先看函数输入是一组字典，接着找到循环，再按条件跟踪正常、缺字段和非正数记录，最后确认返回两个列表。这里 `is None` 专门识别缺失/空值，`<= 0` 是独立的业务规则。真实系统是否允许零、负数或冲销，需要业务契约决定，不能把本例照搬为通用规则。

函数没有验证文本数量、空白编码、重复业务键和每条错误原因。如果输入为文本 `"5"`，不能指望比较代码替你完成可靠转换。输入解析、字段校验和错误分类还需补齐。

列表查找、字典索引和嵌套循环有不同开销。比如逐行扫描另一份完整列表做编码匹配，数据量扩大后工作量可能明显增长；先核对真实规模、算法和查询次数，再决定索引或批量处理，不为了“高性能”盲目引入新服务。

## 企业案例：错误行不能静默丢弃

错误行不能静默丢弃。模拟方案应给每行稳定标识及明确结果：可接受、需修正或结果未知；缺字段与重复编码要有不同原因。上面两个列表只演示控制流，尚不能替代完整的逐行报告。

建议用少量虚构记录分别验证：正常正数、缺数量、零、负数、文本数量、空白编码及重复编码。先确定业务预期，再看代码是否满足。数量汇总一致不证明每行都正确，对账还应检查具体标识和字段。

## AI 易忽视的问题

- 使用 `value or 0` 把缺失与真实零混为一谈。
- 在循环中途跳过记录，没有逐行解释。
- 将解析失败当作合法默认值继续写入。
- 只测一条正常输入，忽略空列表、重复和类型边界。

## PM 评审问题

1. 输入的类型和空值前提是什么，在哪里保证？
2. 每个条件分别保护哪条业务规则，有哪些遗漏？
3. 每行都能追踪到结果及原因吗？
4. 函数会写数据或调用外部服务吗，失败会留下什么？
5. 数据扩大后最频繁的查找和调用发生在哪里？
6. 是否用不同边界输入核对过实际输出？

## 微实践：手工追踪四条输入

对数量为 `3`、`None`、`0`、`"3"` 的四行，先写预期，再按分支走读。前三种在本例有明确路径；第四种超出输入前提，可能触发类型错误。要求 AI 明确入口如何解析并给出拒绝原因，而非直接用零替换。
